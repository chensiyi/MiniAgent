MiniAgent UI 设计（v4 整合稿）

浮于宿主页面的玻璃方框浮层 · 无背景板/标题栏 · 靠右边缘隐藏 · 配置异常才给跳转链接
本文档整合「设计说明 + 交互原型」为单文件；架构背景见 docs/ARCHITECTURE.md。

1. 形态约束

  • 无背景板、无标题栏：UI 直接浮于宿主页面，容器本身透明。
  • 玻璃方框：输入框 / 气泡 / 工具面板均为毛玻璃透明、无圆角（统一方框语言）。
  • 气泡无人物称呼标签：直接放内容，角色仅靠对齐与配色区分（user 右蓝 / assistant 左 / system 中 / error 红）；工具名以正文形式给出。
  • 面板可顶到屏幕上方：浮层高度近满屏，顶部以遮罩逐渐淡化到消失。
  • 靠右边缘隐藏：默认整体隐藏到右边缘，仅留竖向手柄；右侧区域停留 >3 秒自动展开（点手柄亦可）。
  • 配置异常才给跳转：外部工具存储编辑链接仅出现在 System(error) 报错气泡内，常态 UI 无设置/编辑入口。

2. UI 分层与依赖顺序

层职责提供
工具加载器数据底座，UI 极薄已注册工具列表 + 启用状态
chat对话骨架，可独立渲染input(玻璃) · send/stop · message bubble(玻璃) · 工具入口按钮(输入左)
executor叠加在 chat 上输入左侧按钮展开的工具面板 · bubble 上的确认

依赖自下而上；运行时方向 chat → executor（chat 驱动 loop，遇 tool_call 才调 executor）。两层单向依赖，无环。

3. 气泡 Role × State 矩阵

Role状态视觉
usersent玻璃方框，右对齐
assistant(文本)streaming / completed / error左对齐；流式带光标
assistant(工具)pending工具卡 + 批准/拒绝（仅 high/critical）
assistant(工具)running工具卡 + spinner
assistant(工具)result / error工具卡 + 结果/错误
assistant(工具)refused工具卡 + 已拒绝（静音）
systeminfo居中弱样式状态条
system(error)config_error红调玻璃 + 跳转链接（唯一外部入口）

4. 工具状态机

tool_call (来自 LLM)
      │
      ▼
  pending   riskLevel ∈ {high, critical}
  批准│        │拒绝
     ▼        ▼
 running   refused ──► enqueue(refused) 回 chat
     │
  成功/失败
  ┌──┴──┐
result  error

riskLevel ∈ {low, medium}：跳过 pending，直接 running。

拒绝不是静音丢弃：enqueue 一个 refused 结果，LLM 据此调整后续行为。

5. 交互要点

  • 靠边隐藏 / 3 秒展开：默认整体隐藏到右边缘（仅留手柄）；鼠标移到右侧区域停留 >3 秒自动展开，移开自动收起。
  • 顶部淡出：消息超高度后顶部以遮罩渐隐到消失，不与屏幕硬切。
  • send / stop 双态：空闲显示发送；回合进行中显示停止（enqueue control:cancel）。

7. 交互原型

下方为可直接操作的 v4 原型：把鼠标移到右侧区域停 3 秒展开，或点右侧 💬 手柄；展开后点 🔧 看工具面板、点气泡内按钮看状态流转、左上「触发配置异常气泡」看红调报错+跳转链接。

如何为网页注入轻量 AI 助手

技术博客 · 阅读约 6 分钟

现代浏览器扩展可以把智能能力直接叠加在已有页面上，而不必重新搭建一套界面。关键在于让助手以浮层形态存在，随用随唤、用完即隐。

玻璃方框让浮层与页面内容自然融合：输入框与消息气泡半透明，透出下方文字的模糊投影，既美观又不遮挡阅读。

工具入口收纳在输入框左侧，点击展开注册表；配置异常时才在报错处给出跳转链接——常态不打扰用户，异常才引导修复。
