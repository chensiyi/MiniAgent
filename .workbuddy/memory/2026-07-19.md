## 架构方向调整：OOP 单例 + HookedFunction + 事件驱动
- 用户明确设计哲学：以 OOP 为基础，对象只暴露属性+方法；复杂过程用事件驱动，需严格流程控制时用 hook 方法（可拆解/替换/插入）。利用 JS 弱类型做运行时动态编辑。
- llm 对象只存"标准方法"（标准做法是发送全量 messages）；`app.sendMessage = new HookedFunction(() => llm.chat(this.messages))`。
- agent 概念上 == app 本身（用户说的"直接调用"即此意）；不单独建 agent 编排类，编排是 sendMessage 上的钩子。
- 运行在 userscript 空间 → 直接全局单例（globalThis.MiniAgent），便于运行时/LLM 动态编辑。
- storage 是逻辑概念：`agent.storage = { save: GM_setValue, get: GM_getValue }`，不做重类。
- 待逐块设计，起点：HookedFunction 原语（before/after 钩子 + 事件通道）。尚未落地代码，仍处于设计对齐阶段。

## HookedFunction 契约已锁定（2026-07-19）
- 插槽模型：beforeExe/afterExe 为数组，单值赋值自动包成数组；aroundExe/onError 为单插槽。
- 钩子为 leaf HookedFunction（自身不再展开 before/after，避免嵌套）。
- 钩子上下文 CallCtx={args, thisArg, result, meta, skip, replace}；before 可改 args/短路/替换，after 读写 result。
- 调用方式（已按用户纠正修正）：用 `withHooks(fn)` 工厂把**普通函数**包成“可 hook 的普通函数”，外在签名不变，调用方仍 `fn(...args)` 正常调，无需 `.call()`、也不是 class 实例。
- 两阶段：init 写基础过程（普通函数）→ 编排阶段用 `withHooks` 偷偷替换成被 hook 版本，并 `.before()/.after()` 追加钩子（追加不替换基础）。这支持“动态替换”。
- 返回值：已锁定跟随 base 同步/异步（async→Promise、sync→原值、生成器直接返回生成器仅 before 钩子）。呼应“调用方返回没有变化”。
- 推论：所有"过程"方法（sendMessage / llm.chat / llm.streamChat / executor.run）都用 withHooks 包裹，全系统统一可 hook。
- 下一步设计 llm 对象的标准方法（chat / streamChat，均为 HookedFunction 实例，无状态，历史在 app.messages）。
