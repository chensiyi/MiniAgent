# MiniAgent 项目长期约定

## 架构铁律（OOP + withHooks 编排）
- 编排 / 初始化分层（用户 2026-07-19 修正）：会话级编排（系统提示注入、运行态、权限）走 `withHooks` 的 `before/after` 钩子；**工具注册（含 `register`/`unregister` 编排重建）属"进工作循环前的基本初始化"，由 `init()` 在 boot 阶段执行，`executor.register` 即编排重建入口，不走钩子**。仍禁止顶层写死业务装配副作用（默认工具"定义"可顶层声明常量，但"注册动作"放 `init()`）。
- `base` 函数只保留最小核心流程（如队列引擎循环、LLM 调用），所有可控的插入/替换都交给钩子，便于编排方插拔/替换与 LLM 动态编辑。
- 钩子注册示例（用户原设计模式）：`agent.sendMessage.beforeExe.push(fn)`。
- `withHooks(fn, thisArg?)` 返回普通函数；`beforeExe/afterExe` 为数组；钩子 `opts={args,result}`；返回值严格跟随 base 同步/异步。

## 模块职责（锁定）
- `src/core/withHooks.ts` 工厂原语；`src/core/bus.ts` 极简事件总线。
- `src/core/llm.ts` 流式 + 参数补齐(temperature/maxTokens/reasoningEffort) + 响应(reasoningContent/finishReason/usage/model) + 首类 `cancel()`；tools 载荷经 `toOpenAI` 读 `t.inputSchema`（文档称 inputSchema，非 parameters）。
- `src/core/executor.ts`（按 ARCHITECTURE.md §5/§8 对齐）：ToolDef 契约 = `{name, author?, description, inputSchema, deps?, riskLevel?, call?, register?, unregister?}`，`DepRef={name, author?, version?}`，唯一标识 `name+author`；`register/unregister` 写表后触发 `tool.register/unregister`（RegisterCtx={storage,executor,agent,this=agent}），同名 register 先 unregister 旧再 register 新；**依赖解析=先拓扑排序再注册**：`registerAll(tools)` 走 `topoSort`（循环依赖→整体拒绝），单 `register` 校验依赖（缺失→拒绝；author 不符→警告不覆盖）；注册即挂载 `agent[name]`（RESERVED 保护核心属性）+ `agent.tools` 权威表；`list(includeAll)` 默认仅返回有 `call` 的工具（进 LLM 清单，§7），`list(true)` 全量（tool_list/系统提示用）；`run(call,agent)` 注入 RunCtx({storage,executor,agent,this,console})，确认闸读 `riskAtLeast(tool.riskLevel, APPROVAL_RISK_LEVEL)`（阈值可配，非仅 code_run）；编译 `code`/`register`/`unregister` 用 `new Function` 沙箱；默认工具 storage_get/set、code_run(riskLevel=high)、toolregister(原 tool_create，对齐文档自扩展语义)、tool_remove、orchestrate_send(无 call→不进 LLM 清单，仅 tool_list 揭示)、tool_list、session（**无 code_gen**：codeGenTool 由用户 2026-07-20 主动删除，一次性脚本不再提供存储相关复杂设计；session 落盘钩子幂等：模块级 sessionPersistHook/currentSessionId，register 仅首次挂钩、unregister 移除，防重复注册累积/泄漏）；新增 `setEnabled(name,enabled)`（自编排工具改 `tools:<name>.enabled` 持久化、内置工具改 `config.disabledTools` 黑名单持久化，均即时 register/unregister）+ `allToolStates()`（全量含启用态，供 chat_ui 面板）。
- `src/core/storage.ts` 命名空间 API：`get/set/del/keys(namespace, key?)`，内部 `realKey=ns+':'+key`，`keys(ns)` 返回去前缀子键；分区 default(config,sessions)/session/tools/code/memory；`set.afterExe`→`bus.emit('storage:changed')`；新增 `listToolDefs()`（读 tools 命名空间全部 ToolDesc，系统真相源）；`get` 真泛型。
- `src/ui/ui.ts` 原生组件 + 玻璃在气泡上；`chat.*`(普通)/`requestApproval`(withHooks，支持 `{name, code?, riskLevel?}` 并显示风险级别)；**chat_ui 工具启停面板已完成**：输入行「⚙」按钮展开面板，渲染 `executor.allToolStates()`，每行开关调 `executor.setEnabled(name, checked)` 即时生效+持久化（对齐文档 §3 三视图/启停）；**工具执行进度气泡（2026-07-20）**：engine 在 executor.run 前 append('tool','⚙ name: 执行中…')、完成后 updateLast('tool',结果)，updateLast 已泛化支持 tool 角色。ui 与 executor 形成循环依赖（executor import ui、ui import executor），仅方法体内延迟使用，安全。
- `src/agent.ts` 全局单例 `globalThis.agent` + 队列引擎；`agent.tools: Map<name,ToolDef>` 按名挂载权威表；`agent.chat` getter 暴露 `sendMessage`（验收：控制台 `agent.chat.sendMessage('...')` 直接发消息并看到工具调用结果）；`agent.sessionId` 由 session 工具 `register` 生成；`init()` boot 阶段：config 迁移(`migrateFlatToNs`)+`getConfig()`（取 config 含工具黑名单 `disabledTools`）+种子+`executor.attachAgent(agent)`+`defaultTools.filter(剔除 disabledTools)`→`executor.registerAll(bootList)`（拓扑序，黑名单先移出名单）+`executor.rehydrateTools()`（读 `tools:*`→过滤启用项→`buildToolFromDesc`→`registerAll` 拓扑重建）；`orchestrateSystemPrompt` 仍 `sendMessage.beforeExe` 钩子；**运行态按钮(发送/停止)：`sendMessage.beforeExe` 钩子 `setRunning(true, chatStop)` + `engine.finally` `setRunning(false)`（2026-07-20 从 engine.beforeExe 迁移，语义更贴合"消息处理开始前"）**；文件末尾 `(globalThis as ...).agent = agent` 后再 `unsafeWindow.agent = agent`（补偿 userscript 沙箱隔离，使 DevTools 控制台可直接访问 `agent`）。
