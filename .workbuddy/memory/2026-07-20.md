## Trusted Types 兼容修复（用户注入脚本后报 `This document requires 'TrustedHTML' assignment`）
- 根因：页面/用户脚本框架对文档启用 CSP `require-trusted-types-for 'script'`，所有 `innerHTML` 赋值必须是 `TrustedHTML` 对象，源码直接赋字符串被浏览器拦截，`ui.chat.mount`（root.innerHTML）mount 阶段即崩。
- `src/ui/ui.ts`：新增 `setHTML(el, html)` 助手——建一次性 Trusted Types 策略 `createPolicy('miniagent', {createHTML:(s)=>s})`（try/catch + 全局缓存 `__maHtmlPolicy` 防 HMR 重名报错），有策略则 `el.innerHTML = policy.createHTML(html)`，否则回退直接赋值。3 处 `innerHTML`（renderToolsPanel 清空、root 模板、requestApproval 模板）全部改走 `setHTML`。`textContent`/`createElement` 非 sink 不动。
- 验证：`npm run typecheck` 0 错、`npm run build` 0 错（dist 39.82kB）；产物含 `createPolicy("miniagent",…)`。重新注入后 mount 应不再被 TrustedHTML 拦截。
- 复用提示：今后任何 `innerHTML` 赋值都必须走 `setHTML`，勿裸赋。
