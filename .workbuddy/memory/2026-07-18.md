### 给用户的补充（ChatGPT 漏掉的关键点）
1. **jsdelivr 在大陆可达性风险**（最相关）：用户疑似大陆环境，jsdelivr 常被墙/不稳 → @require 失败则 window.React 为 undefined 全崩。建议换 npmmirror/国内 CDN，或干脆内联。
2. jsx-runtime 机制：plugin-react v6 默认自动运行时，externalGlobals 只配 `react` 即可，Rollup 会把 react/jsx-runtime 内联并改写其 react 引用于全局 React —— 不要额外把 `react/jsx-runtime` 配进 externalGlobals（UMD 无该全局，会坏）。
3. 真正的体积大头是 langchain/@langchain/openai（内联），不是 antd；若真要瘦身应评估是否必须整包 langchain。
4. 工具链极新（Vite8/plugin-react6/vite-plugin-monkey8），已验证可用，但需留意大版本回归。

## 架构 pivoting：砍掉 React/antd/langchain，改手写极简原生 DOM（用户要求"最简化，一个输入框"）
- 触发：构建版在真实公网页运行报 `require("react-dom") in environment without require` —— rolldown 不会把 CJS 子模块（react-dom/client、react/jsx-runtime）的 `require("react-dom")` 改写成 externalGlobals 的全局，运行时崩。
- 连带问题：dev 模式 PNA 拦 loopback、jsdelivr 大陆可达性。三堵墙根因都是"把整个 React+antd+langchain SPA 硬打成 userscript"。
- 决策（用户确认"动手"）：放弃框架，手写原生 TS + DOM。
- 改动清单（已执行）：
  - `vite.config.ts`：移除 `@vitejs/plugin-react` 与 `externalGlobals`，entry 改 `src/app/main.ts`，保留 `monkey()` + `build.emptyOutDir:false`。
  - `src/app/main.ts`（新）：手写右下角浮窗（输入框 + 发送按钮 + 消息区），`GM_addStyle` 注入样式，串起 `Agent`。
  - `src/core/llm.ts`：删除 langchain，改用 `@sec-ant/gm-fetch`（默认导出即 `typeof fetch`，走 `GM_xmlhttpRequest` 绕 CORS）直接 POST OpenAI 兼容 `/chat/completions`（非流式）。
  - `src/core/useAgent.ts`：删除 React，改普通 `Agent` 类（`subscribe` 回调驱动重绘）。
  - 删除：`src/app/main.tsx`、`src/app/App.tsx`、`src/view/` 全部。
  - `package.json`：仅保留 `@sec-ant/gm-fetch` + 构建工具；移除 react/react-dom/antd/dayjs/langchain/@types/react/@vitejs/plugin-react。
  - `tsconfig.json`：移除 `jsx: react-jsx`。
- 构建结果：`✓ 7 modules transformed`，产物 **8.96 KB / gzip 3.62 KB**（原 2.29 MB），**无 @require、无 CDN 依赖、react/require/createRoot 引用全 0**。三堵墙一次性消失。

## 抽象分层重构：ui / llm / executor / storage 四大模块 + 工具循环（用户要求"每个部分抽象"）
- 用户要求把系统抽象成 `uiObj{chat,存储编辑}` / `llmObj{chat({stream:true,message})}` / `executor{}` / `storage{get,set}`，`ui.chat` 调 `llm.chat`，返回值被解读可能触发 `executor`，让 LLM 具备自我编辑/管理能力，甚至自我开发。
- 经 AskUserQuestion 确认范围：**code.run 带人工确认闸**（不静默执行任意代码）+ **本版实现流式**。
- 新文件结构：
  - `src/core/storage.ts`：封装 GM_get/set/delete/listValues → `storage.get/set/del/keys`（自动 JSON）。
  - `src/core/llm.ts`：重写为 `llm.streamChat`（AsyncGenerator，解析 SSE，yield 文本 delta 与 toolCall delta）+ `llm.chat`（收集成 {content,toolCalls}）；支持 `tools` 参数。底层用 `@sec-ant/gm-fetch` 的 `res.body.getReader()` 读流（已确认 gm-fetch 返回标准 Response 且 `.body` 为 ReadableStream）。
  - `src/core/executor.ts`：`executor.register/run/list`；预置工具 `storage_get`/`storage_set`/`code_gen`/`code_run`。`code_run` 经 `setApprovalRequest` 注入的人工闸（默认拒绝，未注入绝不执行）；`new Function('ctx', code)` 在受控作用域执行，ctx 含 storage/console。
  - `src/core/agent.ts`：替代旧 `useAgent.ts` 的编排循环——`send(text)` 循环 `streamChat`，逐字渲染 assistant，遇 toolCalls 调 `executor.run` 并将 tool 结果回灌 LLM，直至无工具调用。
  - `src/ui/ui.ts`：从 main.ts 抽出的 `ui.chat.{mount,append,updateLast,setRunning}` + `ui.requestApproval`（确认气泡，allow/deny 按钮 resolve Promise）。
  - `src/app/main.ts`：仅装配 `ui+agent+executor`，`setApprovalRequest(ui.requestApproval)`。
  - `src/model/config.ts`：新增 `SYSTEM_PROMPT`/`getSystemPrompt()`（告诉 LLM 有哪些工具与自我开发规则）+ `REQUIRE_CODE_APPROVAL` 开关。
  - 删除 `src/core/useAgent.ts`。
- 构建：`✓ 10 modules transformed`，产物 **18.47 KB / gzip 6.8 KB**；所有 GM_* 权限自动注入（含 GM_deleteValue/GM_listValues）；react/require/@require 残留全 0。
- 关键安全点（已与用户对齐）：userscript 运行时**不能**改写自身 .user.js；"自我编辑"= LLM 生成代码存 storage（`code_gen`）→ `code_run` 经用户确认后 `new Function` 执行。务必保留确认闸，勿静默执行。
- 注意：当前 config 用 `openrouter/free` 模型，部分免费模型可能不支持 function calling（tools），届时 LLM 不会触发工具但架构仍正常。
- 这是一次较大的可复用架构脚手架，建议后续沉淀为 skill（userscript 内 Agent 工具循环模版）。
